# MySQL 存储契约（前置工作第 1 步）

## 范围与身份

- MySQL 从空库开始。旧本地 JSON 和已删除的 DynamoDB 表不导入。
- 存储实例必须绑定一个非空 `user_id`。本地网页在没有登录功能时使用固定的本地用户 ID；未来云端入口从已验证的 Cognito 身份取得 ID，不接受客户端提交的用户 ID。
- 所有基础简历、公司、职位、版本、面试和任务读写均以 `user_id` 为边界。查不到本用户的 ID 与不存在的 ID 一样返回 `KeyError`，API 映射为 404。
- 本地和云端共用相同的业务表结构与迁移脚本。连接参数来自环境变量，不能写入日志或仓库。

## 现有页面与 API 行为

| 操作 | 输入与结果 | 失败语义 |
| --- | --- | --- |
| 基础简历 | `load/save/delete/reset`；正文以原 JSON 对象返回 | HTTP 层先做 Schema 与必填字段校验 |
| 公司 | 新建、改名、删除；列表按公司、职位、版本嵌套 | 名称非空；删除公司级联职位、版本和面试 |
| 职位 | 名称及非空招聘要求；`revision` 初始为 0，修改时加 1 | 修改须提交预期修订号；过期请求返回冲突，不改变原记录 |
| V1 | 按职位生成一次，保存正文、模块顺序、外观设置及生成时要求快照 | 同职位并发仅一个 V1 成功；删除全部版本后仍禁止再次生成 V1 |
| 手动版本 | 从指定现存版本创建新版本，记录 `source_version_id`、`source_version_number` 与保存时的当前招聘要求 | 版本号按职位严格递增，不重排、不复用；失败不得消耗编号 |
| 删除版本 | 删除指定版本 | 子版本保留来源 ID 和来源编号；现有面试保留创建时快照并标记来源已删除 |
| 面试 | 每职位只保存最新场次；场次保留职位、版本、招聘要求与正文快照，以及最多 12 题 | `expected_status` 不符返回冲突；失败不覆盖已提交的题目和回答 |
| 重置 | 清除本用户基础简历、公司、职位、版本、面试和任务 | 不影响其他用户 |

存储层以 `ValueError` 表示输入或并发冲突，以 `KeyError` 表示不存在或不属于本用户的记录。HTTP 层保留现有 `validation_error`、`conflict`、`not_found`、`version_exists`、`resume_required` 等错误码。MySQL 故障不应伪装为成功或泄露数据库连接信息。

## 原子性与边界

- 公司/职位删除、职位条件更新、版本创建和面试场次替换必须在事务中完成。职位行承担版本计数与修订号的串行化锁。
- 发起 V1 时读取的招聘要求是该版本的快照；生成期间若职位已修改，保存时必须拒绝冲突或显式保持发起时的快照，不得把新要求与旧生成结果错配。
- 基础简历与岗位简历正文使用 MySQL `JSON` 列；招聘要求和快照使用文本列。读取时返回 Python 对象与字符串，保持原有页面契约。
- 旧的 350 KiB 面试记录限制与 12 题限制继续执行，直到统一确定新的正文限制；15 MB 上传限制独立于数据库正文限制。
- 测试仅使用明确标记的虚构数据，覆盖两用户隔离、重新连接恢复、并发版本编号、回滚、删除来源版本和面试状态冲突。
